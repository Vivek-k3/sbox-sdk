## Installation

`@runloop/api-client` is an optional peer dependency of `sbox-sdk`, loaded lazily on first use.

```package-install
sbox-sdk @runloop/api-client
```

## Authentication

<AuthEnv provider="runloop" />

`runloop()` reads `RUNLOOP_API_KEY` when you don't pass `apiKey`. Check the key with `client.verify()`. It lists one devbox and never creates anything.

## Usage

```ts
import { createSandboxClient } from "sbox-sdk";
import { runloop } from "sbox-sdk/runloop";

const client = createSandboxClient({
  provider: runloop({ apiKey: process.env.RUNLOOP_API_KEY! }),
});

const sandbox = await client.create({
  template: "bpt_123",
  metadata: { team: "a" },
});
const res = await sandbox.commands.run("python --version");
console.log(res.stdout);

const forks = await sandbox.fork({ count: 2 }); // snapshot the disk, boot 2 devboxes
await sandbox.pause(); // suspend: memory preserved
```

What `create()` does with your spec:

- [`template`](/templates) is a **blueprint id**. A **snapshot id** (`snp…`) or `fromSnapshot` restores that disk state into a new devbox instead.
- `name`, `metadata` and `env` are passed through.
- It waits with `createAndAwaitRunning`, and throws if the devbox fails to boot.

## Previews

A devbox has a single V2 tunnel that serves every port. `ports.expose(port)` reuses that tunnel, or enables one if there isn't one yet, and returns:

```
https://{port}-{tunnel_key}.tunnel.runloop.ai
```

`auth` follows the tunnel's mode:

- `open` gives `{ type: "public" }`.
- `authenticated` gives header auth: `X-Runloop-Tunnel-Authorization: Bearer <auth_token>`. This doesn't work from a browser WebSocket.

`removeTunnel` takes no port, so `unexpose()` only removes the tunnel after the last exposed port is gone.

## Capabilities

| Capability          |    Level    | Notes                                                 |
| ------------------- | :---------: | ----------------------------------------------------- |
| `list`              |   native    | walks every cursor page                               |
| `pause`             |   native    | suspend/resume (memory preserved)                     |
| `streaming`         |  emulated   | `executeAndAwaitCompletion` returns buffered output   |
| `filesUpload`       |   native    | binary `uploadFile`, wrapped with `toFile`            |
| `exposePort`        |   native    | V2 tunnel                                             |
| `snapshot` / `fork` |   native    | `snapshotDisk`. Fork snapshots, then boots N devboxes |
| `privatePreview`    | unsupported | the tunnel's auth mode is set when it's created       |
| `stop`              | unsupported | `pause` (suspend) or `destroy` (shutdown)             |

Flags:

- `perCommandEnvCwd: false`: the core adds `cwd`/`env` to the command itself.
- `preservesMemoryOnPause: true` and `previewModel: "tunnel"`.
- No in-place snapshot `restore`.

## Known limitations

- `kill()` and `timeoutMs` stop the adapter from waiting and end the command with exit code 137 or a `Timeout` error. The remote process **isn't signalled**, so it keeps running until it finishes on its own.
- The disk snapshot that `fork()` takes isn't deleted afterwards.
